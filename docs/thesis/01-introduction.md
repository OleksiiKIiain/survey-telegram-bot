# АНОТАЦІЯ

Кваліфікаційна робота присвячена управлінню проєктом розробки Survey Bot, системи автоматизованого опитування й аналізу даних з інтерфейсом респондента в Telegram та вебпанеллю адміністратора. Метою є обґрунтування і перевірка узгодженого процесу створення програмного продукту, у якому вимоги до сценаріїв опитування, цілісності даних, локалізації та аналітики пов'язані з архітектурними рішеннями й критеріями приймання.

Об'єкт дослідження: процес управління розробкою систем цифрового опитування. Предмет: моделі, методи планування та засоби забезпечення якості проєкту на основі FastAPI, PostgreSQL, aiogram і React. Використано аналіз вимог, порівняльний аналіз аналогів, функціональне й інформаційне моделювання, декомпозицію робіт, оцінювання ризиків, інспекцію вихідного коду та експериментальне тестування.

Результатом є програмний артефакт з REST API, чотирма типами питань, українсько-англійським представленням анкет, JWT-авторизацією адміністратора, аналітикою та експортом CSV/XLSX. Під час аудиту встановлено і виправлено дефекти збереження ідентифікаторів варіантів, перевірки завершення сесій, експорту та відтворюваності збирання. Проведено окремі інтеграційні й HTTP-перевірки з реальною PostgreSQL. Показано межі достовірності демонстраційної статистики та необхідність відокремлювати технічне тестування від дослідження користувацької ефективності.

Ключові слова: управління ІТ-проєктами, автоматизоване опитування, Telegram-бот, REST API, PostgreSQL, мультимовність, цілісність даних, аналітика, тестування.

# ABSTRACT

This qualification thesis addresses project management for Survey Bot, an automated survey and data analysis system combining a Telegram respondent interface with a web administration panel. Its objective is to substantiate and evaluate a coherent development process linking survey workflows, data integrity, localization and reporting requirements to architectural decisions and acceptance criteria.

The research object is the management of digital survey system development. The subject comprises planning models, implementation methods and quality assurance practices for a FastAPI, PostgreSQL, aiogram and React solution. The study combines requirements analysis, comparison of existing products, functional and information modelling, work breakdown, risk assessment, source code inspection and experimental software testing.

The resulting software supports a REST API, four question types, Ukrainian and English questionnaire fields, JWT administrator authentication, analytical summaries and CSV/XLSX exports. The audit identified and corrected defects affecting option identity preservation, session completion checks, export safety and build reproducibility. Integration and HTTP tests were performed against a real, isolated PostgreSQL database. The study distinguishes software verification from empirical claims about respondent behaviour and documents the limits of demonstration data and external translation availability.

Keywords: IT project management, automated surveys, Telegram bot, REST API, PostgreSQL, localization, data integrity, analytics, software testing.

# ВСТУП

Збирання зворотного зв'язку є лише початковою частиною управлінського циклу. Для прийняття рішень потрібні також контроль структури анкети, відокремлення завершених і перерваних проходжень, відтворювані підрахунки та зрозуміле представлення результатів. Якщо ці операції виконуються різними непов'язаними засобами, зміна тексту питання або втрата відповідності варіантів може зробити підсумкову діаграму недостовірною. Тому автоматизація опитування розглядається в роботі як проєкт створення цілісної інформаційної системи, а не як реалізація окремої команди Telegram.

Практичною основою дослідження є Survey Bot: відкритий репозиторій із сервером FastAPI, ботом aiogram, базою PostgreSQL та адмін-панеллю React [@repo]. Вибір наявного програмного артефакту дає змогу перевіряти твердження про функціональність на рівні моделей, маршрутів, клієнтських форм і результатів тестування. Це принципово відрізняє дослідження від проєктування гіпотетичної системи: висновок про реалізацію функції робиться лише за наявності відповідного коду, а висновок про працездатність конкретного сценарію потребує окремої перевірки.

Актуальність теми визначається необхідністю поєднати зручний канал участі респондента з керованим процесом розробки та контролем якості даних. Telegram обрано каналом діалогу, але його популярність сама по собі не є доказом вищої якості вибірки або кращої завершуваності анкет. Методологія опитувань вимагає враховувати охоплення цільової сукупності, спосіб залучення та похибки відповідей [@aapor]. У роботі ці питання відокремлено від технічної перевірки API.

Мета дослідження полягає в обґрунтуванні та практичній перевірці підходу до управління проєктом розробки системи автоматизованого опитування й аналізу даних засобами Telegram Bot та вебтехнологій, який забезпечує простежуваність між вимогами, моделями, реалізацією та результатами приймальних тестів.

Для досягнення мети поставлено такі завдання: охарактеризувати предметне середовище та сценарії застосування; порівняти альтернативні засоби; сформувати вимоги і критерії приймання; спроєктувати інформаційні потоки, модель даних та життєвий цикл сесії; побудувати WBS, план робіт і реєстр ризиків; дослідити фактичну реалізацію Survey Bot; виявити та виправити підтверджені дефекти; провести доступні інтеграційні, HTTP- та інтерфейсні перевірки; оцінити обмеження й визначити умови подальшого впровадження.

Об'єктом дослідження є процес управління розробкою інформаційної системи цифрового опитування. Предметом є моделі планування, архітектурні рішення та процедури контролю якості, які забезпечують узгоджену роботу Telegram-інтерфейсу, REST API, PostgreSQL та вебпанелі адміністратора.

Методи дослідження охоплюють системний аналіз для визначення меж продукту; порівняльний аналіз для вибору функціонального обсягу; UML та ER-моделювання для опису поведінки й даних; декомпозицію робіт для планування; якісне оцінювання ризиків для пріоритизації; статичну інспекцію коду для виявлення дефектів; експериментальні програмні тести для перевірки гіпотез про поведінку реалізації. Описова статистика використовується для інтерпретації контрольних даних, а не для узагальнення думок населення.

Практичне значення полягає в отриманні відтворюваного локального продукту й набору перевірок, які можна використати для демонстрації повного циклу опитування та навчання управлінню ІТ-проєктами. Окрему цінність має регресійна перевірка збереження ідентичності варіантів під час редагування перекладів: вона пов'язує зміну інтерфейсу з достовірністю накопиченої аналітики.

Методологічною опорою є дослідження через проєктування артефакту. Peffers та співавтори пов'язують визначення проблеми, цілі рішення, розробку, демонстрацію та оцінювання в межах design science research [@dsr]. У цій роботі артефактом є не лише код, а й узгоджений набір моделей, критеріїв приймання та тестів. Оцінювання обмежено технічними властивостями реалізації; поведінкову ефективність для широкої аудиторії не доведено.

Елементом новизни в межах прикладного дослідження є узгодження вимог двомовного редагування з інваріантами історичних відповідей та приймальними тестами. Не заявляється винайдення нового алгоритму опитування, статистичного методу або загальної методології управління. Власний внесок у досліджувану ітерацію становлять аналіз наскрізних сценаріїв, формалізація критеріїв якості, виправлення підтверджених дефектів і побудова доказового набору тестів.
