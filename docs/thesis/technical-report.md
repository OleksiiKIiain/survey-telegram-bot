# ТЕХНІЧНИЙ ЗВІТ АУДИТУ SURVEY BOT

Дата: 15.11.2026. Базова версія: 7929c0c. Гілка виправлень: codex/thesis-audit. Основний репозиторій: https://github.com/OleksiiKIiain/survey-telegram-bot. Цей звіт відокремлює результати інспекції коду, інтеграційні перевірки та зовнішні обмеження.

## Середовище та захист даних

Docker Compose успішно зібрав і запустив PostgreSQL 16, API на Python 3.12, aiogram polling bot та Vite frontend на Node 22. Основна БД під час перевірки містила 4 анкети, 15 сесій і 56 відповідей. Реальні відповіді не видалялися; том PostgreSQL не скидався. Для змінних тестових даних створено БД survey_audit_20261115, API localhost:8001 та frontend localhost:5174.

Перший запуск старої команди автоматично виконав старий repair_answers; у логах зафіксовано Repaired answer option links: 0. Історичне виконання цього скрипта до поточного аудиту не досліджено за резервною копією. Попередньо підставлені ним значення не можна вважати відновленими первинними відповідями.

## Перевірки

Інтеграційні тести: 7/7 успішні, повторний запуск 0,498 с. Це виклики серверних операцій із реальною PostgreSQL. HTTP-тести: 25/25 успішні через окремий Uvicorn. Протокол: docs/thesis/http_audit.json. Перевірено JWT, службовий ключ, CRUD тестової анкети, чотири типи відповідей, завершення, скасування, аналітику, CSV та XLSX.

UI-тест виконано реальним headless Microsoft Edge через Playwright. Перевірено вхід, перемикання UA/EN, сторінки списків, аналітику, створення анкети, редагування EN-тексту, явне повідомлення збереження та повторне читання після reload. Протокол: docs/thesis/evidence/ui_audit.json. Скриншоти отримано з тестової БД. У протоколі окремо зафіксовано помилки браузера та горизонтальне переповнення.

Production build: успішний. Залишилося попередження про JS bundle понад 500 kB; отриманий bundle 721,75 kB до gzip. Попередження не трактувалося як помилка TypeScript або відсутність сторінки.

Додатково виконано 8/8 unit-тестів FSM бота за 0,012 с: блокування іншої анкети й старої кнопки мови, збереження активного стану після /start, /help лише на запит, скасування через API, локалізовані тексти та шкала від нуля. Мережеві виклики тут замінено AsyncMock. Цей результат не є реальним Telegram E2E та не доводить доставлення повідомлень платформою.

## Непідтверджені та негативні результати

Автопереклад у реальному HTTP-запуску повернув 503. Збереження введених вручну двомовних текстів підтверджено окремо; якість успішного машинного перекладу не оцінювалася. Polling вийшов у роботу для @survey_oa_bot, але повне проходження анкети через справжній Telegram-клієнт у цьому аудиті не завершено. Mock або прямий API-запит не називається Telegram E2E.

Методичка, звіти практик та основний Google Docs недоступні через поточні підключення. Зміст цих документів не вигадувався. Google Drive не встановлено; авторизований браузерний доступ завершився тайм-аутом підтвердження. Локальні документи створюються за вимогами завдання, а не за перевіреним додатком Е.

## Залишкові ризики

FSM зберігається у пам'яті; restart втрачає активний діалог. Немає серверної унікальності однієї активної сесії на користувача. Старі шкальні callback потребують прив'язки до question_id. Немає UNIQUE для пари session_id/question_id; послідовна заміна не гарантує конкуренцію. JSONB option_ids не має поелементних FK. Видалення варіантів або питань після збирання відповідей може втратити історичний зміст.

Збереження форми складається з кількох HTTP-запитів і може бути частковим. Не реалізовано пагінацію великих списків та UI-фільтр дат. Аналітика містить запит на кожне питання. Немає перевіреного rate limiting, refresh-token процесу й тесту відновлення резервної копії. Пароль demo admin відомий, тому локальну конфігурацію не можна переносити у публічний сервіс без зміни реквізитів.
