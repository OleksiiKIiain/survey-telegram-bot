# Аудит цілісності та локального запуску

Цей документ описує зміни коду та відтворювані перевірки. Він не містить дампів, первинних відповідей, профілів респондентів, секретів, скриншотів або тексту магістерської роботи.

## Виправлення

- OptionUpdate зберігає ID варіанта в PATCH; React не відкидає його під час редагування тексту. Це запобігає втраті посилань існуючих відповідей.
- Завершення сесії перевіряє обов'язкові питання. Повторне завершення ідемпотентне; cancelled не можна завершити.
- /cancel фіксує cancelled через API до очищення FSM. /start, інша анкета та стара мовна кнопка не очищують активний сценарій.
- Службовий API перевіряє X-Bot-Key; JWT sub перевіряється до int; неактивний адміністратор не отримує токен.
- Шкала підтримує нуль; пробільний текст відхиляється; сторонні поля відповіді не записуються; повторні ID множинного вибору усуваються.
- CSV/XLSX екранують формульні префікси. Первинний текст у БД не змінюється.
- Кількість респондентів аналітики визначається за відібраними сесіями.
- Seed не перезаписує існуючі анкети. repair_answers є read-only аудитом; автоматичну підстановку втрачених виборів вилучено зі startup.
- Додано видиме збереження, фіксовану нижню панель, повторне читання серверних ID та перестановку питань у редакторі.
- Версії frontend зафіксовано, додано lockfile та npm ci. moduleResolution Bundler усуває несумісність зі старим Node-режимом у TypeScript 7.
- PostgreSQL не має зовнішнього порту. Backend/frontend прив'язані до loopback. Бот очікує здоровий backend.

## Ізольовані перевірки

```powershell
docker compose up -d --build
docker compose exec db createdb -U survey_user survey_audit_local
docker compose run --rm --no-deps -e DATABASE_URL=postgresql+psycopg://survey_user:survey_password@db:5432/survey_audit_local backend alembic upgrade head
docker compose run --rm --no-deps -e DATABASE_URL=postgresql+psycopg://survey_user:survey_password@db:5432/survey_audit_local backend python -m unittest discover -s tests -v
docker compose run --rm --no-deps bot python -m unittest discover -s tests -v
docker compose run --rm --no-deps frontend npm run build
```

Повторний createdb не потрібний, якщо тестова БД уже існує. Основна БД survey_bot не використовується для тестового очищення. Backend-тести перевіряють префікс назви БД та працюють із реальною PostgreSQL. Bot-тести явно використовують AsyncMock мережевих викликів.

У локальному аудиті пройшли 7 інтеграційних тестів backend, 8 unit-тестів FSM та 25 HTTP-умов на окремому API. Перевірено розбір CSV/XLSX, збереження перекладу та контрольні агрегати. Production build успішний; залишається попередження про JS bundle понад 500 kB. Зовнішній перекладач повернув 503, тому успішний переклад не підтверджено.

HTTP-скрипт backend/tests/http_audit.py потребує окремого Uvicorn, окремої audit-БД із seed та налаштованого токена бота. Він не є Telegram-клієнтом і не повинен запускатися на основній БД. Сирі протоколи та зображення цього аудиту залишаються локально.

## Залишкові ризики

FSM зберігається у пам'яті; перезапуск не відновлює діалог. Старі числові callback потребують прив'язки до question_id. Немає унікального обмеження для пари session_id/question_id та однієї активної сесії користувача. JSONB option_ids не має поелементних FK. Структурне видалення питань/варіантів після отримання відповідей може втратити історію.

Збереження всієї форми не атомарне, немає пагінації та UI-фільтра дат. Відсутній повний rate limiting, перевірений backup/restore та реальний Telegram client E2E. JWT у localStorage потребує контролю XSS. Цей набір виправлень не є підтвердженням готовності до публічного production-розгортання.
